# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Контекст

Кейс хакатона НТУ «Сириус» × Видеофор (8–10 октября 2026): найти эпизоды поведения, похожего на курение, в видео
стационарных CCTV-камер (Гатчина). Требования кейса — в `Сириус_Хакатон_Видеофор.pdf`, план и обоснование
решений — в `PLAN.md`, инструкции запуска — в `README.md`. Документация, комментарии и логи в коде — на русском.

Правила кейса, которые влияют на код:
- Главная метрика — Event F1. Предсказание засчитывается, если интервал совпадает с эталоном (эталон расширен на ±3 с, пересечение ≥ 1 с) **и** IoU рамки человека в `peak_sec` ≥ 0.3. Поэтому пайплайн работает по отдельным людям, а не по клипу целиком.
- Положительный эпизод: ≥ 2 полных цикла «рука ко рту → пауза 0.5–5 с → отвод» за 20 с ИЛИ 1 цикл + прямой признак (сигарета/вейп/дым). Циклы одного человека объединяются при паузе ≤ 15 с; события разных людей не объединяются.
- Пороги подбираются только на эталонном наборе. До фиксации `manifest.json` и предсказаний скрытый набор нельзя использовать для подстройки.
- Видео объекта нельзя публиковать и отправлять в облачные сервисы: вся обработка локальная. Видео лежат в `videos/` и `data/` и исключены через `.gitignore` — **не коммитить их**.

## Команды

Окружение: `.venv` (Python 3.11, создано через uv). В uv-venv нет pip, поэтому автоустановка зависимостей
в ultralytics не работает: новые пакеты ставить так: `uv pip install --python .venv/bin/python <pkg>`.
На Windows интерпретатор — `.venv/Scripts/python.exe` (в командах ниже `.venv/bin/python` — путь macOS/Linux).
Версии закреплены в `requirements.txt`, полный снимок проверенного окружения — `requirements.lock`; при
обновлении пакетов пересоздавайте его через `uv pip freeze --color never`.

```bash
.venv/bin/python -m pytest -q tests                                   # все тесты (без моделей, < 1 с)
.venv/bin/python -m pytest -q tests/test_logic.py::test_merge_gap     # один тест
.venv/bin/python run.py --input videos/1.mp4 --camera-id cam1 --out runs/x --render   # один клип
.venv/bin/python run.py --inputs data/hidden.csv --out runs/final     # набор клипов (CSV: video_path,camera_id[,clip_id,start_time,roi])
.venv/bin/python evaluate.py --pred runs/x/predictions.csv --gt gt.csv --durations runs/x/processing_log.csv --out runs/x/report
.venv/bin/python tune.py --inputs ref.csv --gt ref_gt.csv --out runs/tune --grid episode.confidence_threshold=0.3,0.5 [--cv clip|camera|none]
```

Любой параметр переопределяется через `--set section.key=value`. Линтера и сборки в проекте нет.

## Архитектура

Пайплайн разделён на две стадии, чтобы перебор порогов не требовал повторной детекции:

1. **`Pipeline.track()`** — тяжёлая стадия (`smokedet/tracking.py`). YOLO-pose + ByteTrack на каждом `stride`-м кадре (~10 кадр/с), для мелких людей поза уточняется на кропе. На том же кадре `flash.LightMeter` меряет новый пересвет (нет в фоне — скользящей медиане кадров) у рта/кисти и в кольце вокруг человека. Результат — `TrackSet` с сырыми наблюдениями (bbox + 17 точек COCO + `light`). Он не зависит от ROI и порогов, поэтому кэшируется в `<out>/cache/<clip_id>_tracks.pkl`. Ключ кэша (`pipeline.track_cache_key`) — видео (размер и mtime) + хэш секций `detector` и `video` конфига + хэш содержимого YAML трекера. Время наблюдения — pts кадра из контейнера (`io_video.FrameClock`, в CCTV-файлах с переменным fps `idx/fps` уходит до 0.7 с); если pts негоден, до конца клипа берётся `idx/fps` со сдвигом, без скачка. `render.py` считает время так же.
2. **`Pipeline.analyze(clip, trackset, cfg)`** — лёгкая стадия, зависит только от порогов. `tune.py` вызывает её много раз с разными `Config` (логика подбора — `smokedet/tuning.py`: точка сетки выбирается по F1, сглаженному по соседям на сетке, а не по одиночному пику; перекрёстная проверка «оставить клип/камеру» оценивает переобучение и не требует повторного анализа). Последовательность: склейка треков (`stitch_tracks`) → `geometry.build_signal` (нормированное расстояние кисть→рот `d(t)`; кадры вне ROI или с ростом < `min_person_height` дают NaN; анатомически неправдоподобная рука — длиннее `max_upper_arm`/`max_forearm`·scale или с запястьем дальше `max_wrist_outside`·scale за рамкой, обычно чужая в толпе, — в отсчёте не учитывается; эта проверка только здесь, `LightMeter` её не делает) → `cycles.detect_cycles` (конечный автомат с гистерезисом `near_enter`/`near_exit`; отброшенные циклы остаются в списке с `valid=False` и `reject_reason`; признак `head_tilt` — подъём носа над ушами в паузе, фильтр `max_head_tilt` по умолчанию выключен) → `verifier.verify` (open-vocab детектор на узком и широком кропах паузы; заполняет `direct`/`neg_fraction`/`strong_negative` и может пометить цикл невалидным; затем у людей с валидными циклами просматривает весь трек (шаг `track_scan_step`) на «двойников» сигареты из `track_negative_classes` — чупа-чупс, палочку которого в паузе принимают за сигарету — и предметы для питья из `track_drink_classes` (свои пороги `track_drink_*`; на локальных данных питьё от курения не отделяют, порог консервативный) и отбрасывает циклы рядом с находками: `reject_reason=track_object:*`) → `flash.find_flashes` + `attach_flashes` (вспышка зажигалки отмечает `flash` у валидных циклов рядом по времени; при `episode.flash_as_direct` это прямой признак) → `vapor.VaporMeter.measure` (у валидных циклов перечитывает кадры: фон до подхода руки, дымка у рта вокруг конца паузы; заполняет `vapor`/`vapor_net`, `nan` — человек идёт или зону закрыли соседи; при `episode.vapor_as_direct` это прямой признак; кэш в памяти, как у верификатора) → `episodes.build_events` (правило эпизода, объединение, confidence; цикл, начавшийся не позже `min_cycle_gap` после конца предыдущего, — то же движение (`joined_prev`) и в `min_cycles` отдельно не идёт; рамка события — медиана рамок трека в ±`box_window` от пика; `Event.passed` = confidence ≥ порога и нет `reject_reason` — событие отклоняется, если «чужие» предметы видны в ≥ `event_negative_fraction` его циклов без прямого признака).

Далее `export.event_records` берёт только события с `passed`, а `render.py` строит ролик с отметками по уже готовому `Analysis`.

Неочевидные моменты:
- `configs/default.yaml` обязан совпадать с dataclass-значениями по умолчанию в `smokedet/config.py`; это проверяет `test_config_roundtrip`. При добавлении параметра правьте оба файла. Неизвестные ключи в YAML или `--set` вызывают ошибку. Значения приводятся к типу значения по умолчанию (`config._coerce`): `--set detector.device=0` — строка `"0"`, а не число, одиночная строка для списка классов — список из одного элемента.
- Относительные пути к весам и конфигу трекера считаются от корня проекта (`pipeline.project_path`), пути в CSV со списком клипов — от самого CSV.
- Трекер сбрасывается между клипами вызовом `model.track(..., persist=False)` на первом кадре клипа. Уточнение позы использует **отдельный** экземпляр `YOLO`: `predict()` на основной модели запустил бы колбэки трекера.
- Константы замера света (`SAT`, `BG_*`, `ZONE_RADIUS` в `smokedet/flash.py`) влияют на кэш треков, но не входят в его ключ: при их изменении поднимайте `tracking.CACHE_VERSION`. `flash.py` импортирует `geometry`, а та — `tracking`, поэтому `tracking` импортирует `LightMeter` лениво внутри `run()`.
- Кадры для верификатора и пара перечитывает `io_video.FrameReader` по последовательному индексу, как у трекера. Seek по `CAP_PROP_POS_FRAMES` в OpenCV считает номер по pts·fps и на файлах с переменным fps промахивается на величину дрейфа, поэтому дальний переход идёт по времени кадра из трекера (pts): `reader.get(idx, t)`. Кадры с синтетическим временем (`VideoMeta.synthetic_from`, его пишет трекер; в старых кэшах поля нет — `None`) читаются подряд.
- Не передавайте `half=False` явно: в ultralytics 8.4 это даёт предупреждение на каждом кадре (см. `PoseTracker._half`).
- Кэш верификатора — в памяти, по ключу `(clip_id, frame_idx, рамка кропа, imgsz, словарь, порог предсказания)`; модель запускается с `PREDICT_CONF`, а `cfg.conf` применяется при агрегации, поэтому сетки tune.py по conf, геометрии, imgsz и спискам классов дают свежие результаты (при смене классов словарь задаётся заново). Кэш пара (`VaporMeter`) включает отпечаток сигналов клипа. Если open-vocab модель не загрузилась (нет CLIP или весов), верификатор переключается на COCO-модель и работает только с негативными классами.
- Словарь YOLO-World «запекается» в `weights/<модель>-vocab-<хэш списка классов>.pt` (без кэшированного CLIP, ~26 МБ): если файл есть, CLIP не нужен. После правки списков классов запустите `tools/prepare_weights.py` с интернетом, иначе офлайн верификатор откатится на COCO. В `manifest.json` — фактический файл весов и `clip_used`.
- `manifest.json` пишет git-коммит с суффиксом `-dirty`, если есть незакоммиченные изменения в отслеживаемых файлах (неотслеживаемые видео и `runs/` не в счёт). Перед финальным прогоном код должен быть закоммичен.
- Формат эталона в `smokedet/evaluation.py::parse_items` — предположение. Если организатор выдаст валидатор и формат, адаптировать нужно эту функцию.

Веса скачиваются ultralytics автоматически в `weights/` (git их не отслеживает); `tools/prepare_weights.py` скачивает все веса конфига (вкл. COCO-откат `yolo11s.pt`) и запекает словарь — запускать до выезда. Выбор pose-модели пока открыт: по умолчанию стоит `yolo11m-pose`, кандидат — `yolo26m-pose`. Он полностью совместим, скорость на MPS та же, официальный COCO mAP выше. Окончательно выбирать на эталонном наборе.
