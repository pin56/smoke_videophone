# Веб-интерфейс повтора анализа (для жюри)

Цель — показать на защите, как система приходит к решению: видео с разметкой и ход анализа синхронно с ним.

## Решения
- Режим — **повтор**: готовый анализ (кэш треков + `analyze`) проигрывается вместе с исходным видео.
  Экран показывает только то, что анализ «знает» к текущей секунде (`reveal_t`): цикл — после отвода руки,
  событие — когда набрано правило эпизода. Переключатель «показать всё» снимает ограничение.
- Платформа — веб на `127.0.0.1` без новых зависимостей: stdlib `ThreadingHTTPServer`, статика без CDN.
  Видео не покидает машину.
- Видео играет браузер (`<video>`, H.264). Время анализа — pts кадра, `currentTime`/`mediaTime` браузера —
  тоже pts, поэтому пересчёт времени не нужен. Не H.264 или не mp4 — прокси через ffmpeg в `<out>/ui/`.

## Компоненты
- `ui.py` — CLI: те же входы, что у `run.py` (`--input`/`--inputs`, `--roi`, `--config`, `--set`, `--device`),
  плюс `--port`, `--no-browser`. Клипы обрабатываются в фоне по очереди; прогресс трекинга виден в UI.
- `smokedet/ui/payload.py` — `TrackSet` + `Analysis` + `Config` → JSON: треки (время, рамка, 17 точек, рот,
  кисть, d, valid), циклы, события, вспышки, контуры ROI, пороги, лента с русскими текстами, `reveal_t`.
- `smokedet/ui/server.py` — очередь клипов, маршруты `/`, `/static/*`, `/api/clips`, `/api/clips/<id>`,
  `/video/<id>` (HTTP Range — без него браузер не перематывает).
- `smokedet/ui/static/` — `index.html`, `app.js`, `style.css`: видео + canvas-оверлей (ROI, рамки по
  состоянию, скелет, линия кисть→рот, значки признаков), шкала времени, графики d(t) по людям, карточка
  правила эпизода, лента анализа.
- `PoseTracker.run` / `Pipeline.track` — необязательный колбэк прогресса.

## Тесты
`payload` (сериализация, `reveal_t` события, тексты причин) и сервер (Range, неизвестный клип, статика,
выход за пределы папки статики) — на синтетических данных, без моделей.

## Вне рамок
Правка порогов из UI, живой просмотр трекинга, RTSP, галерея кропов верификатора.
