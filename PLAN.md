# План: детекция курения по видео (хакатон Сириус × Видеофор)

Кейс: найти эпизоды поведения, похожего на курение, в видео со стационарных камер (Гатчина, площадка «Юность»).
Основная метрика — Event F1. Событие — эпизод одного человека: интервал времени + рамка человека в момент `peak_sec`.

## 1. Архитектура пайплайна

```
видео + camera_id + start_time + маска ROI
  │
  ├─ 1. Детекция + поза + трекинг ── YOLO11-pose + ByteTrack (анализ ~10 кадр/с)
  │        ├─ для людей ниже ~220px: повторный прогон позы на увеличенном кропе
  │        └─ замер света: новый пересвет (нет в фоне) у рта/кисти и в кольце вокруг человека
  ├─ 2. Склейка оборванных треков ─ разрыв ≤2с, близкое положение → один person_track_id
  ├─ 3. Сигнал по человеку ─ нормированное расстояние «кисть → рот» d(t)
  │        └─ кадр не учитывается, если человек вне ROI или ниже 80px
  ├─ 4. Детектор циклов ─ конечный автомат: подход → пауза 0.5–5с → отвод
  │        └─ фильтры: рука у уха (телефон), кисть ниже локтя, нет фазы подхода
  ├─ 5. Верификатор предметов ─ YOLO-World на 3–4 кропах «рот+кисть» в момент паузы
  │        ├─ сигарета / вейп / дым → прямой признак
  │        └─ бутылка / чашка / телефон / еда → отбросить цикл или снизить confidence
  ├─ 5а. Вспышка зажигалки ─ пересвет у рта ≥ 2 отсчётов, вокруг человека темно, кисть у лица
  │        └─ прямой признак для валидных циклов того же человека (−2 с … +10 с)
  ├─ 6. Правило эпизода ─ 2 цикла за 20с ИЛИ 1 цикл + прямой признак; объединение при паузе ≤15с
  │        └─ confidence из качества циклов и признаков → порог
  └─ 7. Выход ─ predictions.csv/json, manifest.json, журнал времени, ролик с отметками
```

### Почему такой подход

- Метрика требует IoU рамки человека ≥ 0.3 и отдельное событие на каждого человека в группе, поэтому классификатор
  всего клипа не подходит — нужен подход «человек → трек → жест».
- Правило из брифа (цикл, пауза, 2 цикла или 1 цикл + признак) почти напрямую переводится в логику над позой:
  она объяснима и настраивается по 4–8 эталонным клипам, а дообучение на таком объёме данных не сработает.
- Модель поиска предметов (open-vocabulary детектор YOLO-World) отличает курение от питья, телефона и еды без
  собственного датасета. Тяжёлую VLM по возможности не берём: облачные сервисы для видео объекта запрещены
  без письменного разрешения, а локальная VLM на ноутбуке работает медленно.

## 2. Структура репозитория

```
run.py                  # одна команда запуска (файл, RTSP или CSV-список клипов)
evaluate.py             # метрики строго по протоколу (TP/FP/FN, F1, FP/h, задержка, IGNORE)
tune.py                 # перебор параметров на эталонном наборе по закэшированным трекам
tools/draw_roi.py       # разметка маски зоны мышкой по первому кадру → roi.json
configs/default.yaml    # все пороги в одном месте, целиком попадают в manifest.json
configs/bytetrack_cctv.yaml
smokedet/
  config.py             # dataclass-конфиг, загрузка YAML, переопределения --set key=value
  io_video.py           # чтение видео с шагом, метаданные, чтение кадра по индексу
  roi.py                # маска зоны интереса (PNG или полигоны JSON, include/exclude)
  tracking.py           # YOLO-pose + ByteTrack, уточнение позы мелких людей, склейка треков
  geometry.py           # рот, кисть, нормировка, сигнал d(t) по треку
  cycles.py             # конечный автомат циклов жеста и фильтры
  verifier.py           # open-vocab проверка предметов на кропах
  episodes.py           # правило эпизода, объединение, confidence
  render.py             # обработанный ролик с отметками
  export.py             # predictions.csv/json, manifest.json, processing_log.csv, debug
  pipeline.py           # оркестрация по клипу
  evaluation.py         # логика протокола оценки
tests/                  # синтетические сигналы → циклы/эпизоды; кейсы протокола оценки
README.md  requirements.txt  .gitignore
```

`.gitignore` обязательно исключает `data/`, `*.mp4` и прочие видео, `runs/`, `weights/`: исходные записи
публиковать и передавать третьим лицам нельзя.

## 3. Ключевые решения по модулям

| Модуль | Решение |
|---|---|
| Трекинг | Порог детекции 0.1 (ByteTrack использует неуверенные детекции во втором проходе), `track_buffer` ≈ 5 с, трекер сбрасывается на каждый клип |
| Мелкие люди | Для bbox ниже ~220px — поза на увеличенном кропе, замена ключевых точек, если уверенность выше |
| Склейка треков | Конец трека A и начало трека B: разрыв ≤ 2 с, расстояние центров ≤ 0.6 высоты bbox, без пересечения по времени |
| Рот | В COCO-позе точки рта нет: нос (или глаза, или уши) со смещением в сторону середины плеч |
| Кисть | Запястье + 0.3 × (запястье − локоть); берётся ближайшая ко рту рука |
| Нормировка | max(ширина плеч, 0.12 × высота bbox), скользящая медиана за 2 с — человек может приближаться к камере |
| Цикл | Гистерезис: вход при d < 0.6, выход при d > 0.9. Начало цикла — начало подъёма руки, конец — завершение отвода (как в правилах границ события) |
| Фильтры цикла | Пауза вне 0.5–5 с (с допуском); кисть ближе к уху, чем ко рту (телефон); кисть ниже локтя; не видна фаза подхода |
| Верификатор | 3–4 кропа за время паузы. Прямой признак — сигарета/вейп/дым в ≥ 2 кропах. Если в большинстве кропов «чужой» предмет и нет позитивного — цикл отбрасывается |
| Вспышка | Пламя на CCTV — белое пятно без цвета, YOLO-World его не видит. Фон — скользящая медиана кадров; вспышка — площадь нового пересвета у рта/кисти ≥ 0.8·scale² и ≤ 0.6·scale² в кольце вокруг рамки (дверь, фары светят и на окружение). Считается в проходе трекера, хранится в кэше |
| Эпизод | Квалифицирующие циклы: ≥ 2 полных цикла в окне 20 с или цикл с прямым признаком. Объединение при паузе ≤ 15 с. События разных людей не объединяются |
| Confidence | 1 − ∏(1 − 0.45·q_цикла), буст за прямой признак, штраф за «чужие» предметы. Порог подбирается на эталоне |
| Мин. высота | 70–80px: срабатывание на интервале IGNORE не штрафуется, поэтому небольшой запас ниже 80px полезен для recall |
| Кэш | Треки сохраняются на диск, поэтому перебор порогов в `tune.py` занимает секунды |

Качество цикла `q` учитывает длительность паузы (оптимум 0.8–3.5 с), глубину сближения кисти и рта и уверенность
ключевых точек.

## 4. Входы и выходы

**Вход:** видеофайл или поток, `camera_id`, `clip_id`, `start_time`, маска ROI. Пакетный режим — CSV:
`video_path,camera_id[,clip_id,start_time,roi]`.

**Выход:**

- `predictions.csv` / `predictions.json` — одна запись на событие:
  `camera_id, clip_id, event_id, start_sec, end_sec, confidence, label=smoking_like, person_track_id, peak_sec, x1, y1, x2, y2`
  (рамка человека в момент `peak_sec`, в пикселях исходного кадра);
- `manifest.json` — порог, правила объединения, версия модели, полный конфиг и его хэш, git-коммит, веса и их хэши,
  лицензии, промпты верификатора, состав дообучения («нет»), оборудование;
- `processing_log.csv` — длительность клипа, время обработки, во сколько раз быстрее реального времени, устройство;
- `debug/<clip_id>.json` — все циклы, включая отброшенные, с причиной (для разбора ошибок);
- `rendered/<clip_id>.mp4` (флаг `--render`) — ROI, рамки людей, подсветка паузы у рта, красная рамка
  `SMOKING-LIKE 0.82` во время события.

## 5. Оценка и подбор порогов

- `evaluate.py` повторяет протокол: эталон расширяется на ±3 с, требуется пересечение ≥ 1 с и IoU рамок ≥ 0.3,
  сопоставление жадное один к одному по наибольшему пересечению. Предсказание не считается FP, если ≥ 50% его
  длительности попадает на IGNORE и оно не пересекает положительный эталон.
- Метрики: precision, recall, F1, FP на час отрицательного видео, медианная задержка `max(0, start_pred − start_gt)`.
- Отчёт разбирает FP по сценариям N01–N08 и FN по P01–P08 — готовый раздел «разбор ошибок».
- `tune.py` перебирает сетку параметров (`--grid episode.confidence_threshold=0.3,0.4,0.5`) и сортирует по F1, затем по FP/h.
- Пороги подбираются **только на эталонном наборе**. По скрытому набору ничего не меняется до фиксации manifest и предсказаний.

## 8. Риски

- **Мелкие люди в дальней зоне.** Ключевые точки лица на 80–120px шумят. Помогает уточнение позы на кропе и
  `imgsz=1280`; при нехватке — `yolo11x-pose`.
- **Питьё и еда.** Жест тот же, что при курении. Защищают верификатор предметов и правило «2 цикла» (пьют обычно
  1–2 раза с долгой паузой). Вероятно, главный источник FP.
- **Муляж сигареты почти не виден** на разрешении CCTV. Основная ставка — правило двух циклов, прямой признак — бонус.
- **Вспышка зажигалки** видна только при засветке лица (темно, крупный план); днём огонёк в несколько пикселей не
  ловится. Порог площади подобран на одном примере — уточнять на эталоне (`flash.min_area`, `flash.max_ring`).
- **Смена ID при перекрытии** (P05, группы). Лечится склейкой треков; при необходимости BoT-SORT с ReID.
- **Скорость на ноутбуке.** Анализ ~10 кадр/с вместо полного FPS, верификатор только на кадрах паузы, кэш треков.

## 9. Вопросы организаторам

1. Объём съёмки: на слайде 10 — 12 + 12 эпизодов, а сценарии на слайдах 12–13 дают 24 + 24.
2. Название поля: `person_track_id` (формат предсказаний) или `person_gt_id` (сценарий P07). Нужны формат эталона и валидатор.
3. IoU считается по рамке эталона в его `peak_sec` или в `peak_sec` предсказания?
4. Формат маски зоны (PNG или полигоны) и смысл красных, жёлтых и фиолетовых полигонов на примерах кадров.
5. Время в предсказаниях — только относительно начала клипа или нужно и абсолютное (от `start_time` файла)?
